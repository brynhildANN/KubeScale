# KubeScale 阶段计划

阶段按依赖顺序推进。每一阶段完成后保留可演示、可验收的结果；后续阶段建立在前一阶段的接口和部署基线上。

## 阶段 0：环境与契约

**目标**：建立可重复的开发、部署和验证环境，固定第一版的责任边界。

**完成内容**：

- 建立 Go、Vue、部署、示例和测试目录；确定配置格式与运行方式。
- 搭建本地 Kubernetes 环境、Prometheus、kube-state-metrics 和演示应用；应用暴露 CPU 相关指标所需的 Request 与 HTTP 请求指标。
- 定义策略字段、CPU/RPS 计算方式、API 契约和 SQLite 初始模型。
- 准备最小权限 ServiceAccount/RBAC 与基础部署文件。

**验收标准**：可在集群中访问演示应用；Prometheus 可查询其 RPS 和资源指标；Go 服务可只读查询目标 Deployment 的 Scale 状态。

## 阶段 1：核心伸缩闭环

**目标**：完成从指标到副本变更的端到端链路。

**完成内容**：

- 实现 Prometheus 查询、指标有效性与新鲜度校验。
- 实现单策略单 Deployment 的 CPU 或 RPS 目标值计算、上下限约束和控制循环。
- 通过 Kubernetes Scale API 更新副本；处理资源冲突、失败与结果核对。
- 持久化策略和决策记录；暴露控制器自身的基础指标及日志。
- 提供最小的策略与工作负载 API，支持启用、暂停和查看结果。

**验收标准**：在 k6 或等效流量下，RPS/CPU 上升触发扩容、回落触发缩容；所有动作可追溯；指标无效时副本数保持不变；不直接删除 Pod。

## 阶段 2：核心闭环完善与真实控制台验收

**目标**：在阶段一已有实现上补齐关键边界，使真实集群中的策略管理、伸缩结果与决策解释形成可验收的完整流程。

**完成内容**：

- 验证已有连续触发、冷却期、缩容稳定窗口、滚动更新与 Ready 检查，修复发现的边界问题；不重复建设已有机制。
- 验证已有 HPA 控制权冲突检查，包括策略启用与控制循环中的拒绝接管行为；明确只覆盖已支持的冲突来源，暂不扩展到识别所有外部控制器。
- 联调已有策略 CRUD、规则校验及启用、暂停、恢复、删除流程；完善真实模式下接口失败、参数错误和版本冲突的页面反馈。
- 完善已有工作负载及详情、策略和操作记录页面，修复概览中影响核心流程的问题；系统设置保持只读，不扩展页面数量或可编辑连接配置。
- 优先完善 CPU、RPS、目标值与副本变化的展示，使指标、操作时间、候选副本、目标副本、实际结果及执行或跳过原因能够对应核对；通过轮询与手动刷新更新数据。
- 在已有测试上补齐关键缺口，重点覆盖连续触发中断、冷却期、缩容稳定窗口、重启恢复、HPA 冲突、指标失效及 API 管理流程；保留真实集群联调与验收记录。

**范围边界**：沿用单实例、SQLite、本机回环访问和轮询刷新。阶段二不包含 SSE 实时推送、身份验证与权限控制；共享网络部署所需的访问保护另行规划。Pod 资源用量与其他辅助曲线、可编辑系统设置及页面扩展后移，不作为阶段二验收项；已有可用展示保留。告警中心仍属于阶段三。

**验收标准**：

- 在真实集群中通过控制台完成策略创建、启用、修改、暂停、恢复和删除；错误与版本冲突有明确反馈。
- 正常负载变化下扩缩容符合策略，短时波动不产生频繁伸缩；异常指标、未就绪或滚动更新时保守处理，已有 HPA 管理目标时拒绝接管。
- 每次执行、跳过或失败的原因可查，能够结合决策指标、策略参数、副本变化与实际结果核对；页面通过轮询或手动刷新显示新记录。
- 关键安全边界有针对性测试，真实环境验收结果及已知限制有文档记录。

## 阶段 3：告警、压测与交付

**目标**：形成可复现的演示和可运维的交付包。

**完成内容**：

- 配置 Prometheus 告警规则和 Alertmanager；接收 Webhook，保存告警事件并通过 SSE 展示。
- 完成告警中心及工作负载告警上下文。
- 编写 k6 压测场景，覆盖升压、稳态、降压、指标中断、Pod 异常与资源不足。
- 输出扩缩容时延、副本变化、请求延迟、错误率与稳定性的测试报告。
- 完成部署文档、配置说明、故障排查和端到端回归验证。

**验收标准**：按照文档可从空集群部署并复现演示；压测报告可关联负载、指标、伸缩事件和服务表现；告警可在控制台查询并关联工作负载；故障时系统保守处理且留有记录。

## 后续版本候选

Pod 资源用量与其他辅助曲线、可编辑系统设置及其他页面扩展、多集群、多实例高可用、PostgreSQL、Leader Election、更多决策指标与组合策略、完善的租户权限控制。只有在首版闭环与压测结果稳定后再评估这些能力。
