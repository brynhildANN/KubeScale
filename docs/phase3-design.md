# 阶段三设计：告警闭环、验证与交付

## 范围与顺序

延续单实例、SQLite、管理命名空间白名单及现有控制算法。按三步交付：

1. 告警闭环：受保护的 Alertmanager Webhook、持久化生命周期、列表/详情/统计、控制台轮询与工作负载上下文。
2. 实验与交付：固定到达率 k6 场景、独立故障注入、镜像与单实例部署、PVC、监控规则、备份恢复及端到端报告。
3. SSE 增强：只通知告警变化与新增操作；REST 为最终数据来源，重连后重新查询。推送失败不影响入库或控制循环。此项不作为告警闭环前置条件。

## 告警契约

Webhook 使用 Bearer 共享密钥；未配置密钥时禁用接收，最多接收 1 MiB。逐条使用 status，不以组状态覆盖条目。要求 alertname、namespace、startsAt，namespace 必须属于管理范围；workload 标签可选，缺失时保留为空，不推测 Pod 所属 Deployment。规则应直接提供 workload 标签。

实例身份使用排序后的完整 labels 的 SHA-256；触发周期身份再加入 startsAt。同一周期重复 firing 幂等更新，resolved 为终态，迟到 firing 不得复活该周期。再次触发使用新的 startsAt，独立保存；晚到的旧周期恢复不会影响新周期。整个通知事务提交成功才返回 200，失败可由发送方重试。SQLite 重开保留状态，沿用现有 JSON 文档与索引列存储方式。

GET /alerts 支持 namespace、workload、status、severity、分页；GET /alerts/:id 返回详情；GET /alerts/summary 返回选中命名空间/工作负载的全部活动和严重告警统计，不受当前页影响。命名空间越界返回 403，详情也检查管理范围。恢复时间必须不早于开始时间。告警与伸缩决策解耦。

控制台保留轮询，筛选变化重置分页，详情错误明确显示；无 workload 标签时不提供工作负载跳转。概览活动告警来自存储，不再固定为零。Webhook 可达性不能通过“收到过一次通知”推断为持续连通。

## 部署边界

开发默认回环监听；显式 KUBESCALE_ALLOW_REMOTE=true 才允许非回环地址，且必须配置 Webhook 密钥。该配置不提供浏览器身份认证，远程监听只用于受限集群内部；演示浏览器入口使用端口转发，不公开 Service。后续部署采用单副本与 Recreate，避免 SQLite 与控制循环并发运行。

## 告警规则与实验计划

首批规则覆盖持续未就绪、长期 Pending、伸缩失败、指标持续不可用和副本上限持续超目标。正常冷却/稳定窗口不告警。每条规则明确 for 和恢复条件，Pod 归属必须通过监控标签或显式 owner 关联产生，不从名字猜测。

RPS 使用固定到达率并记录 dropped_iterations；CPU 单独校准 work 参数。k6 仅施压，独立脚本执行故障并恢复，测试使用专用命名空间、数据库、运行编号。增加固定副本基线与长期稳态。报告区分施压到决策、决策到 Scale 写入、写入到 Ready、服务延迟/错误率恢复时间；Scale.spec 不代表 Ready。保存策略、负载、操作快照、Ready 序列与客户端结果，不仅保存截图。当前 Pod 集合过滤的历史曲线不可作为完整实验依据。

## 验收与当前交付边界

第一步自动验收覆盖鉴权、大小限制、白名单、重复通知、恢复后迟到 firing、再次触发、事务回滚、重启读取、筛选分页及统计。第二步必须在真实集群验证告警触发/恢复、空环境部署与故障恢复；未经执行不得宣称通过。SSE、完整用户认证、多实例、可编辑系统设置不在第一步范围。
